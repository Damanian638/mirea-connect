# Участие в разработке

Спасибо за интерес к MIREA Connect. Начните с [README](README.md): там описана установка для преподавателей. Режимы работы, настройки и ограничения собраны в [технической справке](docs/technical.md).

## Сообщение об ошибке

Откройте [Issue](https://github.com/Damanian638/mirea-connect/issues) и укажите:

- операционную систему, версию Python и MCP-клиента;
- версию коннектора: `mirea-connect --version`;
- локальный режим stdio или удалённый HTTP;
- шаги воспроизведения, ожидаемый результат и фактическую ошибку;
- дату и время проблемы, если ошибка связана с расписанием.

Удалите из текста и скриншотов персональные данные, cookie, пароли, одноразовые коды и параметры SSO-ссылок. Не загружайте `.env`, базы, ключи, каталог сессий и исходный HTML страницы авторизации. Сообщения об уязвимостях рассматриваются отдельно: [SECURITY.md](SECURITY.md).

## Подготовка окружения

Нужен Python 3.11 или новее. В корне клонированного проекта:

```bash
uv venv --python 3.12
uv pip install --python .venv -e ".[dev]"
```

Linux/macOS:

```bash
.venv/bin/python -X utf8 -m pytest -q
.venv/bin/ruff check .
```

Windows PowerShell:

```powershell
.venv\Scripts\python.exe -X utf8 -m pytest -q
.venv\Scripts\ruff.exe check .
```

Тесты не требуют реального аккаунта: сеть подменяется через `respx` и `monkeypatch`, а хранилища создаются во временных каталогах. В CI также проверяется сборка Docker-образа.

## Как подготовить изменение

1. Создайте ветку с понятным именем и ограничьте изменение одной задачей.
2. Для исправления ошибки добавьте тест, воспроизводящий ошибочное поведение, когда это применимо.
3. Обновите README или справку CLI, если меняются пользовательские команды, параметры или возможности.
4. Запустите тесты и Ruff. Для изменений сборки проверьте `docker build -t mirea-connect .`.
5. Откройте Pull Request: опишите проблему, новое поведение и выполненные проверки.

## Правила реализации

- Учебные инструменты работают на чтение. Новые возможности записи требуют отдельного проектирования и явного описания области действия.
- Не выводите пароль, OTP, токены, значения cookie и полные SSO-ссылки в логи или исключения для пользователя.
- Успешный HTTP-ответ или наличие cookie сами по себе не подтверждают авторизацию. Проверяйте результат прикладного API.
- Не используйте реальные студенческие данные в тестах и документации.
- stdout локального MCP-процесса занят протоколом; диагностический вывод направляйте в stderr.
- Учитывайте московское время и явно заданные даты, не полагайтесь на часовой пояс сервера.
- Сохраняйте совместимость локального и удалённого режимов и сведения об авторах исходного проекта.

## Сторонние зависимости

Библиотека `pymirea` устанавливается из GitHub. Если меняется её API или поведение университетских сервисов, приложите обезличенный тестовый пример. Не публикуйте дампы действующих сессий.
