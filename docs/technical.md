# Техническая справка MIREA Connect

Для первой установки используйте [пошаговую инструкцию для преподавателей](../README.md). Здесь собраны дополнительные настройки и сведения для разработчиков.

## Возможности и ограничения

| Задача | Результат | Нужен вход |
|---|---|:---:|
| Публичное расписание | Занятия группы, преподавателя или аудитории на выбранные даты | Нет |
| Поиск | Группы, преподаватели и аудитории по названию | Нет |
| Свободные аудитории | Помещения без занятий на весь интервал, с фильтром по корпусу | Нет |
| Личное расписание | Ближайшие занятия из Пульса | Да |
| БРС | Баллы по дисциплинам и доступный максимум за посещения | Да |
| Посещаемость | Сводка и статусы занятий по дисциплине | Да |
| Турникеты | Ваши проходы за текущий день | Да |
| СДО | Курсы, ближайшие дедлайны заданий и тестов, доступные итоговые оценки | Да |

**Для преподавателей.** Свое расписание можно искать через публичное расписание преподавателей. Личные методы БРС и посещаемости ориентированы на данные обучающегося и могут не возвращать полезных результатов для преподавательского аккаунта. Доступ в СДО определяется правами учётной записи.

**Границы возможностей.** Коннектор читает учебные данные. Выставление оценок, изменение курса, отправка работ, рассылка сообщений и отметка посещаемости не реализованы. `login` и `delete_my_data` управляют подключением и сохранённой сессией.

Свободная по расписанию аудитория не обязательно открыта физически. Для лабораторий, спецпомещений и объектов с особыми пометками может действовать отдельный порядок доступа. Время — московское, UTC+3.

Не все поля исходного расписания доступны в ответе MCP: например, текущий формат события не сохраняет отдельный список учебных групп.

## Вход и срок сессии

### Как проходит вход

1. Ассистент вызывает `login` и возвращает ссылку `http://127.0.0.1:…`.
2. Вы вводите логин, пароль и запрошенный МИРЭА код на этой странице в браузере.
3. Сервер Пульса создаёт PAR-запрос к университетскому SSO. Коннектор обрабатывает перенаправления и скрытую форму `form_post`.
4. После получения `Pulse.Auth.Cookie` либо прежней `.AspNetCore.Cookies` проверяется ответ `UserService/GetMeInfo`.
5. Только подтверждённая сессия сохраняется. Страница показывает «Готово».

Вход через терминал:

```bash
mirea-connect login
mirea-connect status
```

Пароль в терминале не отображается. **Не передавайте пароль, одноразовый код, cookie и файл сессии в чат.** В локальном режиме пароль проходит через процесс коннектора на вашем компьютере и отправляется в SSO МИРЭА; в удалённом — через сервер, владельцу которого вы доверили подключение.

### Когда потребуется войти заново

Срок определяют серверы МИРЭА. Коннектор **не гарантирует конкретное число часов или дней** и сейчас не сохраняет дату истечения cookie.

- Закрытие чата, вкладки и перезапуск приложения не удаляют сессию.
- Локальные MCP-клиенты и CLI используют общее хранилище.
- Когда сервер перестанет принимать сессию, запрос личных данных потребует повторного входа.
- **15 минут — время работы страницы входа, а не срок авторизации.**
- Публичное расписание и свободные аудитории продолжают работать без входа.

Пульс и СДО имеют разные прикладные сессии. Общий SSO иногда позволяет войти в СДО без повторного ввода данных, но успешный вход в Пульс не гарантирует, что сессия СДО уже создана или ещё действительна.

`status` и `whoami` показывают наличие сохранённой сессии. Её принятие университетом проверяется при обращении к личным данным; наличие локального файла само по себе не является такой проверкой.

### Хранилище и выход

Локальная сессия хранится зашифрованной в `~/.config/pymirea/`, в формате библиотеки `pymirea`. В Windows `~` — каталог пользователя. Путь можно изменить через `PYMIREA_HOME`.

```bash
mirea-connect logout           # удалить локальную сессию
mirea-connect uninstall        # удалить подключения из поддерживаемых клиентов
uv tool uninstall mirea-connect # удалить программу
```

Это отдельные действия. Через ассистента сессию удаляет `delete_my_data` — по вашей явной просьбе. Локальный `logout` не выполняет глобальный выход из всех университетских сервисов.

## Примеры запросов

> Какие пары у преподавателя Иванова Ивана Ивановича в понедельник?

> Покажи расписание ЭФБО-01-24 с 9 по 15 ноября 2026 года.

> Найди свободные аудитории на проспекте Вернадского, 78, 9 ноября с 10:40 до 12:10. Выдай списком.

> Проверь, свободна ли А-214 в этот интервал.

> Покажи мои баллы БРС и посещаемость по физике.

> Какие ближайшие дедлайны в СДО?

> Когда я сегодня проходил через турникет?

При неоднозначном названии сначала используйте поиск. Для преподавательского расписания указывайте полное ФИО; для конкретного дня — явную дату.

## Команды CLI

CLI работает без ИИ-клиента и использует ту же локальную сессию.

```bash
# Личные данные
mirea-connect schedule --days 7
mirea-connect grades
mirea-connect attendance "Физика"
mirea-connect acs
mirea-connect sdo --limit 20

# Публичное расписание
mirea-connect search teacher "Иванов"
mirea-connect timetable teacher "Иванов Иван Иванович" --date 2026-11-09 --days 1
mirea-connect timetable group "ЭФБО-01-24" --days 7
mirea-connect timetable classroom "А-214" --days 7

# Список свободных аудиторий
mirea-connect free-rooms 10:40 12:10 --date 2026-11-09 --campus В-78

# Проверка конкретных аудиторий
mirea-connect free-rooms 10:40 12:10 А-214 ИВЦ-124 --date 2026-11-09 --campus В-78
```

Примеры корпусов: `В-78` — Вернадского, 78; `С-20` — Стромынка, 20; `МП-1` — Малая Пироговская, 1.

У **команд получения данных** есть `--json`:

```bash
mirea-connect timetable group ЭФБО-01-24 --days 7 --json
mirea-connect free-rooms 10:40 12:10 --campus В-78 --json
mirea-connect --help
mirea-connect timetable --help
```

`--days 0` у публичного расписания означает весь доступный диапазон. `acs` возвращает проходы за сегодня, а не произвольную историю.

## MCP-инструменты

| Инструмент | Основные параметры | Назначение |
|---|---|---|
| `search_timetable` | `kind`, `query` | Поиск: `group`, `teacher`, `classroom` |
| `timetable` | `kind`, `query`, `date_from`, `days` | Публичное расписание; дата `YYYY-MM-DD` |
| `free_rooms` | `start_time`, `end_time`, `date`, `campus`, `rooms` | Время `HH:MM`; без `rooms` — список, с `rooms` — проверка указанных помещений |
| `my_schedule` | `days` | Личное расписание на 1–31 день |
| `my_grades` | — | Баллы БРС |
| `my_attendance` | `discipline` | Посещаемость по ID или части названия дисциплины |
| `my_turnstile_events` | — | Проходы за сегодня |
| `my_sdo` | `deadline_limit` | Курсы, дедлайны и доступные оценки СДО |
| `whoami` | — | Режим подключения и наличие сохранённой сессии |
| `login` | `open_browser` | Локальная страница входа; только stdio |
| `delete_my_data` | — | Удаление сохранённой сессии; на удалённом сервере также отзываются токены пользователя |

Пример аргументов `free_rooms`:

```json
{
  "date": "2026-11-09",
  "start_time": "10:40",
  "end_time": "12:10",
  "campus": "В-78"
}
```

## Удалённый сервер

Для MCP-клиентов с поддержкой **HTTP и OAuth**, которые не запускают локальные процессы, можно поднять свой сервер.

| Режим | Где работает | Где хранится сессия | Подключение |
|---|---|---|---|
| Локальный | Ваш компьютер | На вашем компьютере | Команда stdio |
| Удалённый | Ваш сервер | На вашем сервере | `https://ваш-хост/mcp` |

В удалённом режиме пароль проходит через сервер при входе, а зашифрованная сессия остаётся у его владельца. Используйте собственный сервер либо доверенного владельца. Общедоступный сервер проектом не предоставляется.

### Docker Compose

```bash
git clone https://github.com/Damanian638/mirea-connect.git
cd mirea-connect
cp .env.example .env
```

В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env`. Откройте `.env` и задайте `PUBLIC_URL` — внешний HTTPS-адрес без `/mcp`, например `https://mirea.example.com`.

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 mirea-connect
```

- Проверка сервера: `http://127.0.0.1:8000/health`.
- Адрес в MCP-клиенте: значение `PUBLIC_URL` с `/mcp` в конце.
- Порт 8000 опубликован только на `127.0.0.1`; для доступа извне нужен HTTPS reverse proxy или туннель.
- Каталог `./data` должен быть доступен на запись пользователю контейнера с UID `10001`. В Linux при необходимости создайте его и настройте владельца перед запуском.
- Сохраняйте закрытую резервную копию `data`, особенно `data/key`: без ключа сессии не расшифровать.

### Без Docker

```bash
uv tool install https://github.com/Damanian638/mirea-connect/archive/refs/heads/main.zip
PUBLIC_URL=https://mirea.example.com DATA_DIR=./data mirea-connect serve
```

PowerShell:

```powershell
$env:PUBLIC_URL = "https://mirea.example.com"
$env:DATA_DIR = ".\data"
mirea-connect serve
```

При запуске без Docker переменные передаются через окружение. Программа сама не читает `.env`; в Compose это делает `env_file`.

### Туннель

В [docker-compose.yml](../docker-compose.yml) есть профиль Cloudflare Tunnel. Задайте `CLOUDFLARE_TUNNEL_TOKEN` в `.env`, настройте публичный хост на `http://mirea-connect:8000` и запустите:

```bash
docker compose --profile tunnel up -d --build
```

Подойдёт и другой HTTPS reverse proxy или туннель. `PUBLIC_URL` должен совпадать с адресом, который вводится в MCP-клиенте. Некоторые адреса датацентров могут блокироваться университетом; доступность Пульса зависит от сети.

## Настройки

Большинство параметров относится к удалённому серверу. Для обычного локального подключения достаточно значений по умолчанию.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PUBLIC_URL` | `http://localhost:8000` | Внешний адрес; HTTPS для доступа извне |
| `HOST` | `127.0.0.1` | Адрес прослушивания; в Docker `0.0.0.0` |
| `PORT` | `8000` | Порт |
| `DATA_DIR` | `./data` | База и ключ удалённого режима; в Docker `/data` |
| `SESSION_KEYS` | Генерируется в `data/key` | Ключ шифрования; несколько ключей через запятую позволяют ротацию |
| `ALLOW_GUEST` | `true` | Гостевой вход с публичным расписанием |
| `MIREA_PROXY` | Не задан | Прокси для МИРЭА в удалённом режиме |
| `ALLOWED_HOSTS` | Не заданы | Дополнительные значения HTTP Host через запятую |
| `CLOUDFLARE_TUNNEL_TOKEN` | Не задан | Токен контейнера Cloudflare Tunnel |
| `PYMIREA_HOME` | `~/.config/pymirea` | Локальное хранилище CLI и stdio; параметр `pymirea` |

Пример: [.env.example](../.env.example). Настройки сервера: [config.py](../src/mirea_connect/config.py).

## Решение проблем

| Симптом | Что сделать |
|---|---|
| После установки нет инструментов | Перезапустить клиент/MCP; проверить регистрацию через `prompt --json` |
| Клиент не находит программу | Использовать абсолютный путь к Python из `prompt --json` |
| Не открывается `127.0.0.1` | Открыть на компьютере коннектора; через 15 минут вызвать `login` заново |
| «Не удалось получить форму входа» | Обновить пакет из этого репозитория: вход должен начинаться через Пульс с PAR |
| Ошибка после кода | Обновить пакет: нужны поддержка `form_post`, нового имени cookie и проверка API |
| Сессия истекла | Повторить вход; на удалённом сервере переподключить коннектор в клиенте |
| Пульс работает, СДО — нет | У СДО отдельная сессия; общая SSO-сессия могла истечь |
| Нет расписания по ФИО | Сначала `search teacher`, затем точное найденное имя |
| Преподавателю не возвращается БРС | Личные методы ориентированы на студенческие данные; использовать расписание преподавателя |
| На VPS не работает Пульс | Проверить доступ из сети сервера; при необходимости использовать доверенный прокси |
| Ошибка OAuth/Host | Проверить `PUBLIC_URL`, HTTPS, адрес клиента и reverse proxy |
| Docker не может писать `/data` | Проверить права смонтированного каталога |

Обновление установки из GitHub:

```bash
uv tool install --force --python 3.12 https://github.com/Damanian638/mirea-connect/archive/refs/heads/main.zip
```

После обновления перезапустите MCP-процессы, чтобы они загрузили новый код. Локальная сессия хранится отдельно от установленного пакета.

Для сообщения об ошибке укажите ОС, версию клиента/Python и текст ошибки. Удалите персональные данные, параметры SSO-ссылок, пароли, коды, cookie и токены. Не прикладывайте `.env`, `data/` и `~/.config/pymirea/`. Подробнее: [CONTRIBUTING.md](../CONTRIBUTING.md), [SECURITY.md](../SECURITY.md).

## Разработка

Нужен **Python 3.11+**. Скрипты установки используют Python 3.12. `pymirea` устанавливается из GitHub; для установки зависимостей нужен доступ к GitHub и реестру Python-пакетов.

```bash
git clone https://github.com/Damanian638/mirea-connect.git
cd mirea-connect
uv venv --python 3.12
uv pip install --python .venv -e ".[dev]"
```

Linux/macOS:

```bash
.venv/bin/python -X utf8 -m pytest -q
.venv/bin/ruff check .
```

PowerShell:

```powershell
.venv\Scripts\python.exe -X utf8 -m pytest -q
.venv\Scripts\ruff.exe check .
```

Тесты используют временные хранилища и подменённые ответы API. Реальный пароль МИРЭА не нужен. Проверяются PAR, `form_post`, 2FA, оба имени cookie Пульса, результат `GetMeInfo`, локальный вход, удалённый OAuth-поток и установщик. CI запускает тесты на Python 3.11–3.13 и собирает Docker-образ.

### Структура проекта

```text
src/mirea_connect/
  cli.py         Запуск, вход в терминале, управление установкой
  commands.py    CLI для университетских данных
  installer.py   Регистрация в MCP-клиентах
  local.py       stdio, локальная страница входа, сессия
  auth.py        Совместимость SSO: PAR и form_post
  pulse.py       Cookie, GetMeInfo и совместимость БРС
  tools.py       MCP-инструменты
  services.py    Получение и форматирование данных
  server.py      Удалённый HTTP-сервер
  web.py         Страницы удалённого входа
  oauth.py       OAuth-провайдер для MCP-клиентов
  sessions.py    Зашифрованные сессии удалённого режима
  db.py          SQLite
  config.py      Настройки сервера
tests/           Тесты с подменённой сетью
.github/         CI и шаблон сообщения об ошибке
```
